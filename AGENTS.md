# Goodchords

## О проекте

Goodchords — TypeScript-библиотека по музыкальной теории без пользовательского интерфейса. Основной публичный API экспортируется из `src/index.ts`: `Note`, `Interval`, `Chord` и `Scale`. Внутри также есть `NoteLetter` и справочники интервалов, аккордов и ладов.

Проект планируется преобразовать в Nx-монорепозиторий и позднее добавить Angular-приложение, использующее библиотеку. Не начинайте эту миграцию без отдельной задачи.

## Текущее устройство

- `src/note`, `src/note-letter`, `src/interval`, `src/chord`, `src/scale` — доменная логика и тесты рядом с исходниками.
- `src/index.ts` — публичная точка входа npm-пакета.
- `rollup.config.js` — сборка CJS, ESM и UMD в `dist/`.
- `jest.config.js` — тесты Jest через `ts-jest`.
- Менеджер пакетов — npm (`package-lock.json`); требуемая версия Node.js — 22.x.

Основные команды:

```bash
npm test
npm run typecheck
npm run linter
npm run build
```

## Правила изменений

- Сохраняйте библиотеку независимой от UI и Angular; зависимости от приложения не должны попадать в доменную логику.
- Сохраняйте текущий публичный API и форматы сборки, если задача явно не требует их изменения.
- Добавляйте или обновляйте colocated-тесты `*.test.ts` при изменении поведения.
- Перед завершением запускайте как минимум релевантные тесты и `npm run typecheck`; для изменений сборки также запускайте `npm run build`.

## Ориентиры для будущей Nx-миграции

- На первом этапе разумная граница проекта — одна publishable-библиотека музыкальной теории; Angular-приложение должно быть отдельным app-проектом.
- Не разделяйте сущности на Nx-библиотеки механически: сейчас `Chord` зависит от `Scale`, а `Scale` — от `Chord`. Сначала устраните или локализуйте этот цикл зависимостей.
- При переносе сохраните единый публичный entry point, имя npm-пакета `goodchords`, декларации типов и совместимость импортов потребителей.
- Справочные данные и чистую доменную модель отделяйте от Angular-адаптеров и компонентов; приложение должно зависеть от библиотеки, но не наоборот.
